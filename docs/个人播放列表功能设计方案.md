## 一、现状分析

### 已有骨架

`8. 个人播放列表界面` 目录下已有：

| 文件 | 现状 |
|------|------|
| `XCPersonalViewController` | 有 TableView，右侧三个导航栏按钮（+、排序、切换视图），但数据全是硬编码测试数据 |

| `XCPersonalView` | 仅包含 UITableView |

- 依赖库：`WCDBObjc`（Pod 已集成）

## 二、整体设计目标

1. **WCDB 持久化**：播放列表元数据 + 播放列表-歌曲关联均存储到 WCDB 数据库
2. **双视图模式**：封面视图（2 列 CollectionView）和列表视图（TableView）可切换，偏好持久化
3. **特殊"喜爱的歌曲"播放列表**：首次启动自动创建，不可删除
4. **播放列表详情页**：**直接复用** `XCALbumDetailViewController` + `XCALbumDetailModel`，无需新建详情页文件

---

## 三、WCDB 数据模型设计

> **核心原则：不新建数据结构文件，直接在现有的两个数据结构上扩展。**

### 3.1 播放列表实体：改造 `XC_YYAlbumData`

```
修改文件：数据结构/XC-YYAlbumData.h / XC-YYAlbumData.m
```

**现有字段的复用映射：**

| 现有字段 | 在播放列表中的语义 |
|---------|------------------|
| `albumId` | 播放列表 ID（主键） |
| `name` | 播放列表名称 |
| `coverImgUrl` | 封面 URL |
| `artistName` | 创建者昵称（本地创建时留空即可） |
| `authorId` | 创建者 ID（本地创建时留空即可） |

**需要新增的字段（本地 DB 专用，不参与 YYModel 网络映射）：**

| 新增字段 | 类型 | 说明 |
|---------|------|------|
| `createTime` | `NSInteger` | 创建时间（Unix 时间戳） |
| `updateTime` | `NSInteger` | 最近更新时间（用于排序） |
| `songCount` | `NSInteger` | 歌曲数量（冗余存储，避免查询） |
| `isFavorites` | `BOOL` | 是否为"喜爱的歌曲"特殊列表 |
| `sortIndex` | `NSInteger` | 手动排序序号 |

**需要添加的协议：**
- `.m` 文件改为 `.mm`（与 `XC_YYSongData` 一样，引入 WCDBObjc）
- 声明 `<WCTTableCoding>` 并绑定 WCDB 列

> YYModel 和 WCTTableCoding 两个协议完全独立，可以共存。网络 API 返回的 JSON 只填充 YYModel 映射的字段，WCDB 新增字段不参与 YYModel 映射，保持为默认值 0/NO/nil，互不干扰。

### 3.2 播放列表-歌曲关联：改造 `XC_YYSongData`

```
修改文件：数据结构/XC-YYSongData.h / XC-YYSongData.mm
```

**现有字段全部可直接用于播放列表歌曲显示：**

| 现有字段 | 用途 |
|---------|------|
| `songId` | 歌曲主键 |
| `name` | 歌曲名（Cell 展示） |
| `artist` | 歌手名（Cell 展示） |
| `mainIma` | 封面 URL（Cell 展示） |
| `duration` | 时长（Cell 展示） |

**需要新增的字段（播放列表关联专用）：**

| 新增字段 | 类型 | 说明 |
|---------|------|------|
| `playlistId` | `NSString *` | 关联 `XC_YYAlbumData.albumId`（同类型） |
| `sortOrder` | `NSInteger` | 歌曲在播放列表内的排列顺序 |
| `addedTime` | `NSInteger` | 加入播放列表的时间（Unix 时间戳） |

> 同一首歌加入不同播放列表，会在 WCDB 中产生多条记录（`playlistId` 不同），这是正确的关联表行为。在其他使用 `XC_YYSongData` 的场景（专辑、搜索结果）中，这 3 个字段保持默认值 0/nil，不影响现有功能。

**同时完善现有 WCDB 列绑定（`.mm` 里已声明 `WCTTableCoding`，但列映射尚未实现）：**
- 将所有需要持久化的字段绑定为 WCDB 列
- `playlistId + songId` 作为联合逻辑主键（通过查询条件保证唯一性）

### 3.3 数据库管理器：`XCPlaylistDatabaseManager`

```
新建文件路径：Spotify - clone/数据库/XCPlaylistDatabaseManager.h/.m
```

单例，统一管理所有播放列表的 WCDB CRUD 操作：

```objc
// 播放列表操作（操作 XC_YYAlbumData 表）
- (BOOL)createPlaylist:(XC_YYAlbumData *)playlist;
- (BOOL)deletePlaylist:(NSString *)playlistId;
- (BOOL)updatePlaylistName:(NSString *)name forId:(NSString *)playlistId;
- (NSArray<XC_YYAlbumData *> *)getAllPlaylistsSortedBy:(XCPlaylistSortType)sortType;

// 歌曲操作（操作 XC_YYSongData 表）
- (BOOL)addSong:(XC_YYSongData *)song toPlaylist:(NSString *)playlistId;
- (BOOL)removeSong:(NSString *)songId fromPlaylist:(NSString *)playlistId;
- (NSMutableArray<XC_YYSongData *> *)getSongsOfPlaylist:(NSString *)playlistId;
- (BOOL)isSong:(NSString *)songId inPlaylist:(NSString *)playlistId;

// 详情页桥接（已是 XC_YYSongData，直接传给 XCALbumDetailModel.playerList）
- (NSMutableArray<XC_YYSongData *> *)getSongsAsYYDataForPlaylist:(NSString *)playlistId;

// 初始化
- (void)initializeDatabaseIfNeeded; // 首次建表 + 创建"喜爱的歌曲"
```

排序类型枚举：
```objc
typedef NS_ENUM(NSInteger, XCPlaylistSortType) {
    XCPlaylistSortByUpdateTime = 0, // 最近更新（默认）
    XCPlaylistSortByCreateTime = 1, // 最近创建
    XCPlaylistSortByName       = 2, // 名称 A-Z
};
```

### 4.2 播放列表详情页（复用现有代码）

**直接复用** `XCALbumDetailViewController`，**不新建任何详情页文件**。

#### 复用方式

`XCALbumDetailModel` 的四个字段与播放列表数据完美对应：

| `XCALbumDetailModel` 字段 | 填充来源 |
|---------------------------|----------|
| `playerlistName` | `XC_YYAlbumData.name` |
| `mainImaUrl` | `XC_YYAlbumData.coverImgUrl` |
| `timeStr` | `XC_YYAlbumData.updateTime` 格式化为字符串（如 `"3天前"`） |
| `playerList` | `XCPlaylistDatabaseManager.getSongsOfPlaylist:` 直接返回 `NSMutableArray<XC_YYSongData *>` |

#### 无需转换，直接使用

由于播放列表的歌曲本身就存储为 `XC_YYSongData`，从 DB 查出来就是 `NSMutableArray<XC_YYSongData *>`，直接赋值给 `XCALbumDetailModel.playerList` 即可，**不需要任何格式转换**。

#### 跳转逻辑（在 XCPersonalViewController 中）

```objc
- (void)tableView:(UITableView *)tableView didSelectRowAtIndexPath:(NSIndexPath *)indexPath {
    XC_YYAlbumData *playlist = self.model.playlists[indexPath.row];

    XCALbumDetailViewController *detailVC = [[XCALbumDetailViewController alloc] init];
    detailVC.model.playerlistName = playlist.name;
    detailVC.model.mainImaUrl     = playlist.coverImgUrl;
    detailVC.model.timeStr        = [self formatTime:playlist.updateTime];
    // getSongsOfPlaylist: 直接返回 NSMutableArray<XC_YYSongData *>，无需转换
    detailVC.model.playerList     =
        [[XCPlaylistDatabaseManager sharedInstance] getSongsOfPlaylist:playlist.albumId];

    [self.navigationController pushViewController:detailVC animated:YES];
}
```

这样 `XCALbumDetailViewController` 的播放逻辑（点击歌曲调用 `XCMusicPlayerModel`）完全不需要改动，直接生效。

## 八、关键设计决策说明

### 为什么 XC_YYAlbumData 和 XC_YYSongData 可以同时承担 WCDB 职责？

YYModel（`<YYModel>`）和 WCDB（`<WCTTableCoding>`）是两个完全独立的协议，互不干扰：
- YYModel 的 `modelCustomPropertyMapper` 只在 JSON 解析时生效
- WCTTableCoding 的列绑定只在 WCDB 读写时生效
- 新增的本地 DB 字段（`createTime` 等）不会出现在 API 返回的 JSON 里，YYModel 会忽略它们，保持默认值 0/NO/nil

### 关于 XC_YYSongData 存储多条关联记录

同一首歌加入不同播放列表，会在 DB 中产生多条 `XC_YYSongData` 记录（`playlistId` 不同）。这是标准的关联表行为，完全正确。在专辑、搜索等其他场景使用 `XC_YYSongData` 时，`playlistId`/`sortOrder`/`addedTime` 三个字段保持默认值，不影响现有任何功能。

### 关于视图模式切换的动画

两个视图（tableView、collectionView）同时挂在 `XCPersonalView` 上，切换时用 `[UIView animateWithDuration:0.2]` 对 alpha 做淡入淡出，避免频繁 addSubview/removeFromSuperview 造成的布局抖动。

### 为什么详情页可以直接复用？

`XCALbumDetailModel` 本来就是通用的"播放列表"概念（字段名 `playerlistName`、`playerList`），播放逻辑通过 `songId` 调用 `XCMusicPlayerModel`，与数据来源无关。`getSongsOfPlaylist:` 直接返回 `NSMutableArray<XC_YYSongData *>`，赋值给 `playerList` 即可，**零转换、零改动**，省去原计划的 4 个新文件。
